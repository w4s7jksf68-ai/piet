설치와 첫 실행

환경 설치와 예제 위치
Apple Silicon Mac · macOS 13.3 이상 릴리스의 arm64 DMG를 열고 PIET.app을 Applications로 옮긴다. A.1.1 DMG에는 표본 CSV가 들어 있다. 실습 .do는 별도 실습 가이드에서 받을 수 있다.
Windows 10/11 · x64 설치판은 시작 메뉴에 PIET를 추가하고 예제를 문서 폴더의 PIET에 복사한다. 포터블 ZIP은 전체를 푼 뒤 PIET.exe를 연다. 예제는 demo 폴더에 있고 WebView2가 필요하다.
Ubuntu 24.04 이상 · x86-64 .deb 설치 후 앱 메뉴에서 PIET를 연다. 예제는 /opt/piet/demo에 있다. .tar.xz는 전체를 풀고 ./PIET를 실행한다. demo 폴더를 쓰기 가능한 곳에 복사한다.

배포본별 설치 안내 · A.1.1 원본 투어 .do

처음 열어서 결과 하나 얻기

5분 실습. 빈 세션에서 File ▾ → Open sample dataset을 누른다. 아래 명령을 화면 아래 입력란에 한 줄씩 넣고 Enter를 누른다. 여러 줄을 한꺼번에 붙여 넣어 편집기가 열리면 ▶ Run을 누른다.

count
generate frate = fatal / pop * 10000
summarize frate
regress frate beertax

첫 줄은 336을 돌려준다. 자료 한 줄은 한 주의 한 해다. 앨라배마의 1982년 사망자는 839명, 인구는 약 394만 명이다. 두 번째 줄은 839 ÷ 3,942,002 × 10,000 ≈ 2.13명을 만든다. 이렇게 인구 규모를 맞춰야 큰 주와 작은 주를 같은 단위로 비교할 수 있다. 세 번째 줄의 평균은 2.040명, 마지막 표의 beertax 계수는 +0.3646이다.

화면과 버튼

보이는 이름 언제 누르는가
Results · 아래쪽 Run 한 줄을 입력하고 Enter 또는 Run으로 실행한다. 실행한 명령 바로 아래에 표·그림·오류가 쌓인다. 위쪽 내용을 읽다 최신 출력으로 가려면 ↓ latest를 누른다.
File ▾ · Recent Open Data…는 데이터, Open do-file…은 편집할 스크립트, Open sample dataset은 내장 원자료를 연다. Recent에서 이전 파일을 다시 열 수 있다.
Run .do · Do-file Editor 상단 Run .do는 디스크에서 파일을 골라 즉시 실행한다. 편집기 ▶ Run은 현재 편집 내용 전체를 실행한다. ▶ Run selection은 선택한 범위를 실행하며 선택이 비어 있으면 전체를 실행한다. Clear는 편집 내용을 비운다.
Data ▾ Data Browser는 행과 열을 훑는 화면, Data Editor는 값을 직접 수정하는 화면이다. 수정 내역을 반복해서 적용하려면 .do에 replace 명령을 적는다.
Variables · History 변수명·레이블을 검색하거나 변수 카드를 열어 자료형을 본다. 이력 한 줄을 누르면 명령줄로 가져온다. 이력의 → Do-file은 편집기로 보낸다.
Graphics 작은 그림을 눌러 확대한다. Prev / Next로 앞뒤 그림을 보고 Back to gallery로 돌아간다. 파일이 필요하면 결과 그림의 PNG 내보내기 또는 graph export를 사용한다.
Split · Stack · Reset layout Split으로 결과 옆에 편집기나 그림 탭을 붙인다. 편집기와 그림을 모두 붙였을 때 Stack으로 두 보조 화면을 위아래로 배치한다. Reset layout은 처음의 탭 배치로 돌아간다.
Save Results… · × clear Save Results…로 현재 콘솔 내용을 텍스트 로그로 남긴다. × clear는 콘솔을 비운다. 자료는 별도로 save 명령을 써서 저장한다.
Cancel · Submit 긴 do-file은 진행 표시줄의 Cancel로 중단한다. 입력 대화상자가 나타나면 값을 적고 Submit을 누르거나 Cancel run으로 끝낸다. 중단 전 실행된 줄은 이미 적용됐을 수 있다.
About · Settings · 스타일·명암 버튼 About에서 버전과 고지를 확인한다. Settings는 계산·폴더·표시 설정을 연다. 스타일 버튼은 Boring/De Stijl, 명암 버튼은 Light/Dark를 바꾼다.

손에 익힐 키. macOS에서는 ⌘, Windows/Linux에서는 Ctrl을 쓴다. ⌘/Ctrl+Enter는 편집기 전체 실행, ⌘/Ctrl+Shift+D는 선택 실행, ⌘/Ctrl+F는 현재 결과 또는 편집기에서 찾기다. 편집기에서는 바꾸기도 된다. 명령줄의 ↑/↓로 이전 명령을 불러오고 Esc로 열린 패널을 닫는다.

Settings 항목 맞추는 기준
Scratch directory 명령이 쓰는 임시 데이터의 위치다. 큰 자료는 여유 공간이 있는 로컬 디스크를 지정한다. Apply 후 앱을 재시작한다.
Default working directory 상대경로로 자료를 읽고 쓰는 기준 폴더다. Apply 후 재시작한다. 현재 세션만 바꿀 때는 pwd로 위치를 보고 cd “폴더 경로”를 실행한다.
Open do-files in their own folder 켜면 다음에 여는 .do 폴더가 작업 폴더가 된다. 직접 cd를 실행했거나 기본 작업 폴더를 골랐다면 그 선택이 우선한다.
Export folder Save Results와 GUI의 PNG 내보내기 위치다. 비우면 저장 때 물어본다. 스크립트의 graph export는 명령에 적은 경로를 따른다.
Compute cores · Memory budget 전자는 엔진 계산과 BLAS의 총 코어 예산이다. Auto 또는 숫자를 고르고 Apply하면 다음 명령에 적용된다. 메모리 예산은 병렬 작업의 임시 데이터, 콘솔 이력과 그림 보관량, 자동 worker 수에 쓰인다.
Provenance hash 입력 자료의 해시를 결과에 기록한다. 같은 파일로 재현했는지 확인하고 싶을 때 켠다. 기본은 꺼짐이다.
External-library compatibility names 기존 .do의 reghdfe, csdid, boottest 같은 이름을 인식하게 한다. 첫 실행 화면이나 Settings에서 지속 설정한다. 한국어 투어의 set extcompat on은 현재 세션에 적용된다.
Table size limits 빈칸의 기본값은 일원표 12,000행, 이원표 1,200행 × 80열, summarize() 표 375셀이다. 필요할 때 개별 한도를 올린다. 전체 상한은 보통 100만 셀, summarize()는 20만 셀이다.
Editor & results font size 편집기·결과·데이터 브라우저의 글씨 크기를 바꾼다.
Run pasted blocks immediately 켜면 여러 줄을 붙여 넣자마자 실행한다. 꺼 두면 편집기에서 내용을 읽고 실행할 수 있다.
Auto-summarize on load 자료를 열 때 summarize를 실행해 변수 카드의 요약값을 채운다. 기본은 꺼짐이다.
Follow system appearance 운영체제의 밝은/어두운 모드를 따른다. 도구막대에서 명암을 직접 바꾸면 수동으로 전환한다.

두 작업을 실제로 나눠 보기

Settings → Compute cores에서 2개 이상 또는 Auto를 고르고 Apply한다. 다음을 편집기에 넣고 전체 실행한다. 하나는 맥주세를, 다른 하나는 실업률을 요약한다. 두 작업 모두 처음에 열린 같은 자료만 읽는다.

sysuse fatalities, clear
parallel, workers(2) {
    summarize beertax
    summarize unemp
}

결과는 코드 순서대로 평균 0.5133달러, 7.3467%가 나온다. workers(1)로 직렬 결과와 비교할 수 있다. parallel {로 열면 작업 수·코어·메모리·임시 디스크 여유를 고려해 개수를 정한다. 코어는 계산 자원이고 worker는 별도 프로세스다. 같은 블록에서 앞줄이 만든 변수나 추정치를 뒷줄이 쓰는 작업은 순서대로 실행한다. 예컨대 회귀와 이어지는 boottest는 블록 밖에 함께 둔다. 파일을 병렬로 쓸 때는 작업마다 다른 출력 이름을 쓴다.

macOS 배포본의 명령줄에서 위 예제는 표준 오류에 2 tasks / 2 workers를 기록했다. 실행 예시는 "/Applications/PIET.app/Contents/MacOS/piet_native" --do parallel.do이다. 두 개의 작은 요약에서는 프로세스 시작 비용이 커서 시간 단축을 기대하기 어렵다. A.1.1의 Windows에서는 이 블록을 직렬로 실행한다. 엔진 내부의 계산 스레드는 별도로 Compute cores 설정을 따른다. set processors는 이 버전에서 코어 예산을 설정하는 명령으로 쓸 수 없다.

지원 명령과 알려진 제약

처음에는 아래 표에서 할 일을 찾고, 직접 실행할 때는 실습 파일에서 해당 명령을 찾는다. 명령은 보통 명령어 변수목록 if 조건, 옵션 순서로 적는다. 예를 들어 완성 데이터에서 summarize frate if year == 1988은 1988년만 요약한다. 쉼표 뒤 vce(cluster statenum)은 오차를 어느 단위로 묶을지 지정한다.

할 일 자주 쓰는 명령과 사용 예

만들기·정리·결합 generate, replace, egen, label variable, keep, drop, sort, collapse, merge, append, reshape, preserve, restore
회귀·패널·도구변수 regress, xtset, xtreg, reghdfe, ivregress, ivreg2, ivreghdfe. 예를 들어 xtreg의 fe는 주 안의 변화를 사용한다.
이산·제한 종속변수 logit, probit, poisson, nbreg, xtpoisson, tobit, heckman. 종속변수의 단위와 모형에 맞는 predict 옵션을 고른다.

고치는 항목을 읽는 법

공개 릴리스가 밝힌 남은 결함과 플랫폼·문법 제약은 다음과 같다. 2026년 11월 18일 기준 공개 자료에서 개별 항목의 현재 작업자나 수정 예정 버전은 확인되지 않았다. 실습할 때 참고할 수 있도록 영향을 받는 형태와 확인 방법을 적었다.

상태 명령·조합 사용자에게 보이는 차이와 대처
등록된 결함 reshape wide 뒤 label list 값 레이블의 나열 순서가 기준 출력과 다를 수 있다. 코드와 뜻의 대응을 확인한다.
등록된 결함 tabulate a b, summarize(x) 요약값을 계산해도 표가 화면에 그려지지 않는다. 조합별 평균이 목적이면 preserve, collapse (mean) x, by(a b), list, restore를 차례로 실행한다.
투어에서 확인한 제약 absorb(statenum year) 직후 boottest 두 고정효과 흡수에 관한 안내를 돌려준다. 실습 가이드 4절의 연도 더미 명세에서 검정 결과를 확인했다.
플랫폼 차이 Windows의 ustrregexm(), ustrregexra() · sdid, vce(bootstrap) 일부 이모지처럼 U+FFFF를 넘는 문자는 해당 정규식 함수가 거절한다. sdid 부트스트랩 표준오차는 운영체제에 따라 네 번째 유효숫자 부근에서 달라질 수 있다.
예제 자료의 범위 sysuse auto 등 PIET가 함께 배포하는 예제 이름은 fatalities다. 다른 자료는 본인이 보유한 파일 경로로 연다.

A.1.1은 A.1.0의 계산 엔진을 사용한다. 공개 검증은 Stata 19.5와 명령·옵션·오류·저장 결과를 조합한 39,290개 사례 중 32,148개가 일치했다고 보고한다. 3,872개는 Stata에서 실행되지만 PIET가 해당 형태를 미구현으로 응답했고, 1,596개는 PIET에 없는 명령을 사용했다. 한 명령에서 여러 사례가 나오므로 이 수치를 명령어 개수로 읽으면 안 된다. 버전별 검증 결과와 잔여 결함

결과 보관과 막혔을 때

세 파일을 구별하면 과제를 다시 열기 쉽다. .do에는 계산 순서, .dta에는 자료값과 한글 레이블, .log에는 읽을 수 있는 결과표가 들어간다. 그래프 SVG는 별도 파일이다. 제출하거나 공유할 때는 앱·엔진 버전, 사용한 .do, 데이터 출처, 군집 단위, 시드까지 같이 남긴다. CSV에는 PIET 변수 레이블을 담을 자리가 없으므로 편집한 자료는 새 이름의 .dta로 저장한다.
